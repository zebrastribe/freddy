# Contributing Guide

Thank you for considering contributing to the Freddy project! This guide outlines the workflow, coding standards, and best practices for contributors.

---

## Workflow
1. **Fork the repository**
2. **Create a feature branch** (e.g., `feature/your-feature`)
3. **Make your changes**
4. **Test thoroughly** (run all test pages)
5. **Commit with a descriptive message**
6. **Push to your fork**
7. **Open a pull request**

## Branching Strategy
- Use `main` for production-ready code
- Use `feature/*` for new features
- Use `bugfix/*` for bug fixes
- Use `refactor/*` for refactoring

## Coding Standards
- Use ES6+ JavaScript
- Prefer modular code (one class/module per file)
- Use descriptive variable and function names
- Add comments for complex logic
- Keep functions small and focused

## Commit Message Conventions
- Use present tense ("Add feature" not "Added feature")
- Start with a capital letter
- Reference issues if applicable (e.g., `Fix #123`)

## Code Review Process
- All pull requests require review
- Address all review comments
- Ensure all tests pass before merging

## Style
- Use 2 spaces for indentation
- Use single quotes for strings
- End files with a newline
